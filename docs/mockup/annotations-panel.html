In scope = every registered Cornerstone3D tool for the active kind (Segmentation / Structure / Measurement); AI / auto-segmentation tools are deferred (implemented later). Brush family (brush · eraser · threshold · dynamic · spherical variants) are BrushTool strategies shown as distinct buttons. View tools (pan / zoom / scroll / window-level / crosshairs) live in the toolbar, not here. Copy/paste (Ctrl-C / Ctrl-V) and interpolation (a setting) are not tools. Header: <KIND> TOOLS + the active member's name in its own color (all three kinds). Layout: 3 columns of icon+label at full width; as the panel narrows, labels truncate then hide → icon-only (4b, left). Active tool = blue. Greyed (flat) = planned, not yet implemented — temporary; these land right after this project (e.g. Dyn. Thresh, Sph. Brush/Eraser/Threshold, Rect Multi). Dashed + slash = disabled now because there's no FoR-matched viewport for it (D3, e.g. Sphere scissors with no volume viewport).

6 · Inline rename (double-click) & create-in-edit-mode (D7.6)
⏎ save · esc cancel
double-click any name to rename
ROI 1 just created · default name selected — type to replace
Rename: double-click a container or member name → inline edit; Enter commits, Esc cancels (also via kebab → Rename). On create: a new container/member gets a default name and drops straight into edit mode with the text pre-selected, so the user just types. Proposed defaults (open to change): containers → Structure set N / Segmentation N / Measurement set N; members → ROI N / Segment N / (measurement named by its tool, e.g. Length N).

Active = left blue accent bar + filled blue dot ("the pen" — drawing writes here). Selected = inset blue ring + tint (highlighted for an action). Combined = both at once (the active row can also be the selected row). These are the only uses of blue in the list, so blue always means active/selection — never a container type.

Routine save/autosave is surfaced in-place (row spinner / footer strip), never as a toast or banner (CLAUDE.md surface taxonomy, §3.4). A toast is reserved for a user-initiated save that failed or briefly succeeded; a banner only for non-routine high-stakes events.
