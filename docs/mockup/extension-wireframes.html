Extension framework — UI wireframes (X0)

Where an extension's UI appears in Workstation, and how its licence state shows. Drafted for slice X0 of docs/extension-framework.md; drawn from the shipped app as of 2026-10-29. The extension in every picture is the open-source example, Session notes (notes on the open session, stored in an XNAT resource). Its demonstration licence has two tiers: Basic — the sidebar tab and the N / ⇧N keys; Pro — adds the toolbar indicator and the full-window "All notes" view. Wireframes decide where things live and how they behave, not final pixels.

E1 · Sidebar tab

Today the sidebar is the XNAT browser alone, with no tabs. An extension can add one sidebar tab (D10). The tab strip appears only when at least one tab is contributed; an edition with none looks exactly as today.

Scales to many extensions

Behaviour

  • The sidebar's width, drag-handle and collapse are shared by all tabs; each tab keeps its own scroll position.
  • The active tab is remembered per user. If the remembered tab's extension is inactive or removed, Browse opens.
  • The tab body is the extension's own React component, inside an error boundary (E7). It follows the app's focus rule: clicks never leave keyboard focus in the sidebar, except in its text fields.
  • Opening a session from an extension tab goes through the browser's path (hanging protocol, auto-load, the unsaved-changes prompt) — the tab does not switch to Browse.

E2 · Toolbar slot

A compact item an extension shows when it has something to say — a count, a status, previous / next. It is the place the worklist's case bar was reserved (D10).

Unlimited room

Behaviour

  • An item is shown only while the extension says so (e.g. only with a session open), so the toolbar is unchanged when there is nothing to say.
  • Size: one line, at most ~180 px wide. When the window narrows, the item collapses to its icon (the text moves into the tooltip) — the same order of collapse as the centre groups.
  • No colour of its own for urgency: status text and the type colours only. Blue stays reserved for active / selection.

E3 · Full-window view

For work that needs room — a table of every note, a worklist, a form. It replaces the viewport area and the side panels while open; the viewer stays loaded underneath, so going back is instant and nothing is lost.

Two windows to keep in step (sign-out, session changes, modal rules); much more framework work. Can be added later if an extension needs it

Behaviour

  • One full-window view at a time. Opening one is a command, so it can be bound to a key and found with ⌘K.
  • The sidebar is hidden while the view is open; the view can show its own filters instead.
  • An unsaved annotation is untouched by opening the view; leaving the session from the view goes through the usual unsaved-changes prompt.

E4 · Settings › Extensions

A new Settings tab after Modules. It lists what the edition ships — every extension, in every state — with each extension's own Settings page nested beneath it in the Settings list. This is where licence state is shown, in place (no banners or toasts).

E5 · Licence states across the app

A locked feature is absent, not shown disabled: no tab, toolbar item, view, key or ⌘K entry. The only place locked features are named is Settings › Extensions (E4). This keeps the app calm for users who never bought a tier, and means the app never shows a control that cannot work.

Active · Pro

Everything:
  • Notes tab
  • 📝 toolbar item
  • All notes view
  • N / ⇧N, ⌘K entries

Active · Basic

Only Basic's features:
  • Notes tab
  • N / ⇧N, ⌘K entries for them

No toolbar item, no All notes view

Inactive

Nothing in the viewer.
  • Settings row with the reason
  • Its Settings page, to enter a licence

If Notes was the open sidebar tab, the sidebar returns to Browse

Refused / Disabled

Nothing in the viewer.
  • Settings row only

Changes while the app is running

  • Importing a higher-tier licence, signing in to a different XNAT server, or an expiry passing re-evaluates the extension: its features appear or disappear live, with no restart.
  • If a feature disappears while in use (its full-window view open, its tab selected), the app returns to the viewer / Browse. Nothing else is affected, and no unsaved annotation is touched.
  • No notification is raised. The change is visible where it happened and in Settings › Extensions.

E7 · When an extension fails

Each slot is wrapped in an error boundary: a crash is contained to that slot and shown in place.

Sidebar tab

BrowseNotes
Session notes stopped working.
TypeError: cannot read 'items'
Reload extensionCopy details

Toolbar item

⚠ NotesAnnotateTags

A warning icon with the extension's name; its tooltip / popover has the error, Reload and Copy details.

Full-window view

The back bar stays; the body shows the same error card as the sidebar. Back always works.

A failing activation (it throws instead of answering) makes the extension Inactive, with "Failed to start: …" as its reason in Settings.

Copy details puts the error, the extension's id and version, and the app version on the clipboard, for the Issue Report or the extension's publisher.

Rules every slot follows

  • Absence is the default. An edition with no extensions — and an extension with nothing to show — leaves the app exactly as it is today.
  • The app's rules hold inside extension UI: keyboard focus stays on the viewports except in text fields; dialogs carry role="dialog"; blue only for active / selection; no toasts or banners from extensions (R9).
  • Extensions add; they never replace. No slot lets an extension hide or move the app's own controls.
  • The user is always told who drew what where it matters: the extension's name on its toolbar tooltip, its ⌘K entries, its Hotkeys group, its error cards and its Settings.
